# Ручная доработка справочников и проверка резидентуры

Дата: 2026-11-06. Профиль: `SYSADMIN_ASSISTANT`, тестовый логин
изолированный тестовый помощник, без employee_id.

До проверок подтверждено фактическое подключение: `current_database() = corpsite_test`,
локальный PostgreSQL на `127.0.0.1:5432`, ревизия `asst004`.
Браузер использовал только `http://127.0.0.1:3000` с настоящим API на `8000`.
API не подменялся. Рабочая `corpsite`, `.env` и удалённый сервер не изменялись.
Коммита, push, деплоя и миграций в этой доработке нет.

## Что исправлено

- Добавлены Excel-кнопки для видов программ и подготовки, уровней образования,
  видов документов, групп отделений, дерева отделений и рабочих контактов.
- Образовательные справочники заново получают данные с текущими поиском и
  статусом. Общий справочник выгружает отфильтрованные строки; дерево учитывает
  загруженную область оргструктуры и поиск; рабочие контакты используют
  штатный API с поиском, активностью, областью подразделений и пагинацией.
- Заголовки задаются явно. В файлы передаются только значения данных — без
  кнопок, пустого столбца действий и разметки интерфейса.
- В трёх образовательных справочниках помощник больше не получает элементы
  добавления, редактирования и форму изменения, даже если API сообщает can_manage.
  Другие роли сохраняют существующее поведение.
- В общем справочнике помощнику не рисуются кнопки изменения и столбец действий.
  Дерево отделений получает выключенные возможности изменения.
- Общая граница просмотра скрывает остальные кнопки изменения, а не только
  отключает их. Поисковые формы помощника могут отправляться; формы изменения
  остаются заблокированными. Серверные проверки доступа не изменялись.

## Резидентура: сохранение, открытие, уборка

Использован существующий синтетический кадровый субъект тестовой БД:
person_id=1370, состояние карточки `COLLECTING`.
Новые записи обозначались уникальным учебным заведением
`ASSISTANT-RESIDENCY-*`, чтобы не затронуть другие сведения.

Успешный браузерный сценарий, запись education_id=75:

1. Включён режим корректировки карточки, открыта форма образования.
2. Выбраны «Резидентура», университет, тестовое учреждение, специальность,
   начало 2018-09-01, окончание 2020-06-30 и тестовый номер диплома.
3. Нажата кнопка сохранения: настоящий POST API вернул 200.
4. Карточка перезагружена. API вернул ту же запись с `education_kind=residency`.
5. Запись повторно открыта через «Редактировать». Проверены вид образования,
   учреждение и дата начала. Скриншот: `.tmp/assistant-residency-reopened.png`.
6. Через кнопку «Удалить» указана причина завершения теста. Штатный `/void`
   вернул 200.

В предварительном прогоне была также создана education_id=74; она убрана тем же
штатным API после проверки её уникальной тестовой метки. Итоговая проверка БД:
**обе записи имеют lifecycle_status=voided, действующих тестовых записей нет**.
Для обеих записей сохранены `PPR_SECTION_ADDED` и `PPR_SECTION_VOIDED` с actor_id=4350.
Физического удаления и прямого изменения кадровых таблиц для уборки не было.
