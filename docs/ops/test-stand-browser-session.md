# Браузерная проверка тестового стенда

`scripts/ops/test_stand_browser_session.cjs` открывает только `https://test.mmc.004.kz`.
Сценарий сохраняет токен приложения в Playwright storage state между запусками.
При истечении авторизации приложения он выполняет вход повторно. Старую cookie
отключённого шлюза сценарий удаляет из сохранённой сессии.

На тестовом сервере `/opt/projects/corpsite-hire-prep/tools/run-browser-check.sh`
загружает защищённый `browser-check.env` и запускает сценарий. Для проверки страницы
приказов достаточно вызвать этот файл без аргументов. Другую страницу можно указать
через `--path` и `--ready-selector`.

Переменные окружения: `TEST_STAND_URL`, `TEST_STAND_ACCOUNTS_FILE`,
`TEST_STAND_ACCOUNT_KEY`, `TEST_STAND_SESSION_DIR` и
`TEST_STAND_PLAYWRIGHT_MODULE`. Файлы с реквизитами и настройками имеют права `0600`,
каталог сохранённых сессий — `0700`; они расположены вне Git. Файл сессии также имеет
права `0600`. Скрипт не печатает пароли, токены или cookie и не делает скриншоты
страниц входа.

Успешный результат `stand=ready` означает, что защищённая страница загрузилась.
Значения `reused`/`renewed` показывают, потребовался ли повторный вход в приложение. Проверка
`idle_api_requests=0` отслеживает повторные запросы после начальной загрузки.
Ролевые ограничения приложения остаются включёнными. Этот способ авторизует только
браузер сценария.
