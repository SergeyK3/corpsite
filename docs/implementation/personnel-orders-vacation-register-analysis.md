# Анализ книги проверки отпускных кадровых приказов

Источник прочитан без изменений: `Проверка_кадровых_приказов_отпуска_2025-2026.xlsx`.

Основной материал исследования — `Проверка_кадровых_приказов_отпуска_2025-2026.xlsx`. На листе `Классификация` приведены агрегированные количества десяти классов общей суммой 864 события. Арифметическая сумма подтверждена. Построчная сверка и проверка классификации всех 864 событий по данной книге невозможны, поскольку полный исходный реестр событий в ней отсутствует.

## Фактическая структура

| Лист | Строк данных | Назначение |
| --- | ---: | --- |
| `Инструкция` | 8 | показатели и формулы |
| `Нет реквизитов` | 22 | исходные и исправленные номер/дата пусты; все `Проверено кадровиком=Нет` |
| `Ошибки периодов` | 5 | исправленный период и комментарий пусты; все не проверены |
| `Строка перевода` | 1 | перевод в отпускном наборе; реквизиты и решение пусты, не проверен |
| `Классификация` | 10 | предлагаемая агрегированная классификация |

`Нет реквизитов` содержит 16 уникальных блоков и 22 уникальные пары `№ блока`/`№ события`; блок не равен событию. Строка перевода одновременно отмечена как строка без реквизитов, поэтому адаптер сливает её по номеру строки исходного Excel, не создавая дубль.

## Предложенная, но не утверждённая классификация

| Код | Строк |
| --- | ---: |
| `VACATION/ANNUAL` | 429 |
| `VACATION/UNPAID` | 326 |
| `VACATION/PAID_OTHER` | 49 |
| `VACATION/CHILDCARE` | 20 |
| `VACATION/RECALL` | 17 |
| `VACATION/MATERNITY` | 10 |
| `VACATION/EXTENSION` | 5 |
| `VACATION/EARLY_RETURN_UNPAID` | 1 |
| `VACATION/UNCLASSIFIED` | 6 |
| `PERSONNEL/TRANSFER` | 1 |
| **Итого** | **864** |

Сумма подтверждена внутри листа. `UNCLASSIFIED` не готов к применению; `TRANSFER` не является отпуском. Для `RECALL`, `EXTENSION`, `EARLY_RETURN_UNPAID` нужен доказуемый идентификатор исходного отпуска, иначе строка остаётся review-записью.

## Соответствие и gap

| Исходное поле | Нормализованное/review поле | Обязательность | Решение |
| --- | --- | --- | --- |
| строка Excel, блок, событие | `source_row_id`, `block_number`, `event_number` | да | добавлены staging metadata |
| исходный файл/текст/реквизиты | `source_values` | да | evidence без подмены |
| исправленные реквизиты/период | `hr_correction` | нет | только при `Проверено=Да` и решении |
| категория/подкласс | `proposed_values` | нет | предложение, не справочник |
| комментарий/решение/проверка | review поля | да для закрытия review | не официальный факт до подтверждения |

Базовый `PERSONNEL_ORDERS_REVIEW_IMPORT` не подходит: его XLSX предполагает подтверждённые реквизиты и `employee_id`. Введён отдельный `PERSONNEL_VACATION_REGISTER_REVIEW_IMPORT` / `…_V1`, который допускает непривязанного сотрудника только в review-staging и не создаёт официальные приказы, события, сотрудников или назначения.

Ключ документа: нормализованные номер+дата+хеш источника. Ключ события: документ + блок + событие + source row. Ключ связи с сотрудником: событие + явный технический `employee_id` после ручной проверки. Номер+дата сами по себе не являются ключом строки.
