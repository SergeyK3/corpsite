# Двуязычные кадровые приказы: отпуск по уходу, реквизиты документа

## Нормативная граница

Это два самостоятельных действия, которые не следует объединять ни по тексту, ни по коду:

| Код | Русское название | Қазақша атауы |
|---|---|---|
| `LEAVE.CHILDCARE.GRANT` | О предоставлении отпуска без сохранения заработной платы по уходу за ребёнком до достижения им возраста трёх лет | Бала үш жасқа толғанға дейін оның күтіміне байланысты жалақы сақталмайтын демалыс беру туралы |
| `RETURN_FROM_CHILDCARE_LEAVE` | О выходе на работу из отпуска по уходу за ребёнком | Бала күтіміне байланысты демалыстан жұмысқа шығу туралы |

Предоставление регулируется статьёй 100 Трудового кодекса РК. Досрочный выход до окончания отпуска — пунктом 4 статьи 100. Пункт 3 устанавливает сохранение рабочего места и не является основанием досрочного выхода. Официальные тексты: [RU](https://adilet.zan.kz/rus/docs/K1500000414), [KK](https://adilet.zan.kz/kaz/docs/K1500000414).

Исходный DOCX требований содержит русское «Разрешить отпуск…» в контексте выхода и ссылку на пункт 3; это не нормативный шаблон и не переносится в генератор.

## Классификация и источники

- `LEAVE.CHILDCARE.GRANT`: распознаётся только при явной паре «предоставить/беру» и «отпуск по уходу за ребёнком/бала күтіміне байланысты демалыс».
- `RETURN_FROM_CHILDCARE_LEAVE`: распознаётся только при явном «выход/приступить к работе» после отпуска по уходу или `демалыстан … жұмысқа шығу`.
- Одна лишь фраза «вышла на работу» не классифицируется: требуется ручная проверка.
- ФИО берётся только из связанного `employee_id`; должность, подразделение, ставка и дата включаются лишь из структурированных полей item/текущего подтверждённого назначения. Старый payload назначения не переносится.
- Для предоставления начало и окончание берутся из `period_start`/`period_end`; отсутствие любой даты не заполняется предположением.
- Основание выхода: п. 4 ст. 100. Внутреннее кадрово-юридическое правило, требующее иной ссылки, остаётся вопросом подтверждения, а не скрытой заменой.

Обезличенные формы: RU выхода — «[ФИО], [должность] [подразделение], с [дата] приступить к работе в связи с выходом из отпуска по уходу за ребёнком [на ставку].» KK выхода — «[күні] бастап [бөлімше] [лауазым] [Аты-жөні] бала күтіміне байланысты демалыстан жұмысқа шығуға рұқсат берілсін.» RU предоставления — «Предоставить [ФИО], [должность] [подразделение], отпуск … с [дата] по [дата].»

## Образование, сертификат, стаж

### Подтверждённые локальные источники (инвентаризация 2026-09-25)

Инвентаризация выполнена только соединением `127.0.0.1/corpsite` с транзакцией
`READ ONLY`; значения работников и исходные JSON в этот документ не переносились.

PPR-карточка подтверждает те же границы: `app/api/ppr_mappers.py` выдаёт секции
`PPR_EDUCATION`, `PPR_TRAINING`, `PPR_EMPLOYMENT_BIOGRAPHY`; их команды описаны в
`app/api/ppr_card_command_router.py` (и личный маршрут `app/api/ppr_self_router.py`).
В JSON-полях этих трёх таблиц полезных значений нет: `metadata`/`provenance` во всех
соответствующих строках пусты. API стажа `POST /intake/employment-tenure/calculate`
является stateless-расчётом общего стажа и принимает дату расчёта, но не является
источником стажа по основной должности.

Авторитетный источник образования — подтверждённая запись `person_education`, а не совпадение строки должности. Медицинская категория должна поступать из структурированного классификатора должностей: врач — «Образование: высшее.» / `Білімі: жоғары.`; средний медперсонал — «Образование: среднее профессиональное образование.» / `Білімі: орта кәсіптік білім.` При отсутствии такой классификации строка не создаётся.

Сертификат выбирается только для основной должности и её подтверждённой специальности: действующий на дату приказа, с датой выдачи не старше пяти лет; при нескольких — наиболее поздняя дата выдачи, затем ближайшее окончание. Обязательны специальность, выдача, окончание и явная связь с работником и основной специальностью. Если хотя бы один атрибут не хранится, сертификат не выводится. Формы: `Сертификат «…» до ДД.ММ.ГГГГ.` и `Сертификат «…» ДД.ММ.ГГГГ жылға дейін.`

Стаж — только по основной должности, на дату приказа, из существующего расчёта трудовой биографии; дополнительные назначения и общий стаж не смешиваются. При невозможности расчёта: `Стаж работы ещё не определён.` / `Жұмыс өтілі әлі анықталмаған.`

Словарная пара: `медсестра-анестезистка` — `анестезист мейіргері`. В генераторе и
печатном представлении это один узкий exact-match: регистр и обычные варианты дефиса
нормализуются лишь для поиска пары. Существующее заполненное поле `kk` всегда имеет
приоритет и никогда не перезаписывается переводом.

Правило сертификата для будущего подключения: запись должна быть связана с работником
и основной должностью, иметь официальное название специальности, дату выдачи и дату
окончания; на дату приказа срок должен быть действующим, а выдача — не старше пяти лет.
Из подходящих записей выбирать наиболее позднюю дату выдачи, затем ближайшую дату
окончания. Пока в модели отсутствуют три обязательных атрибута, правило не исполняется
и строка сертификата не генерируется.

Правило стажа: применять только нормализованный источник, который доказывает основное
назначение/специальность и интервалы, обрезанные датой приказа. Текущий источник умеет
считать лишь общий стаж, поэтому безопасный результат сейчас всегда: `Стаж работы ещё
не определён.` / `Жұмыс өтілі әлі анықталмаған.`

## Подпись, ознакомление, исполнитель

После подписи директора в печатном представлении для каждого item с работником выводится отдельный блок: KK «Бұйрықпен таныстым…», «Аты-жөні…», дата; RU «С приказом ознакомлен(а)…», «Фамилия И.…», дата. Автоподстановка — RU `Фамилия И.`, KK `И. Фамилия`; дата не подставляется автоматически.

Фактическое ознакомление хранится на уровне item/работника с датой, регистратором, временем и идемпотентным аудитом. Личный кабинет остаётся read-only. Многофигурантный документ содержит по блоку на item; личная проекция не раскрывает другой item.

Для минимальной модели ознакомления необходимы: `order_id` и `employee_id` (FK),
фактическая необязательная дата, пользователь-регистратор (FK), время записи,
контролируемая идемпотентность и audit изменения. Нельзя использовать существующий
onboarding-лист: он относится к другому предмету. Для исполнителя потребуется
непустой lifecycle-аудит с явным действием регистрации и связанный `users.employee_id`;
до этого допустим только явно утверждённый fallback, а не текущий пользователь или login.

### Реализованная минимальная регистрация ознакомления

Реализована append-only таблица `personnel_order_acknowledgement_events` (migration
`pojson006`), но её ключ предметной области — **`order_id + employee_id`**, не item:
один работник в нескольких активных пунктах одного приказа имеет один текущий статус.
События `RECORDED`, `CORRECTED`, `CLEARED` не изменяются и не удаляются; актуально
последнее по паре. Дата обязательна для первых двух и `NULL` для очистки. API доступен
только существующему `require_personnel_admin_or_403`, проверяет активный item работника,
дату от даты приказа до текущей даты и делает повтор той же даты no-op. Он не создаёт
`employee_events`, назначения или payload. Личный кабинет к этому API не подключён.

В HR-печатном документе footer формируется по уникальным работникам: RU `Фамилия И.`,
KK `И. Фамилия`; при неразрешённом субъекте имя пусто. Зарегистрированная дата выводится,
иначе остаётся строка для ручной записи. Исполнитель пока централизованно возвращается
как `М. Умерзакова`: `created_by` не считается регистратором без подтверждённого
lifecycle-события регистрации.

Исполнитель берётся из достоверно сохранённого регистратора и его связанной карточки; иначе временный fallback `М. Умерзакова`. Не используется текущий зритель или login. Печатный текст: `Исполнитель: …` / `Орындаушы: …`.

## Первичные материалы и ограничения

Read-only инвентаризация: шесть PDF «Жеке құрам бойынша бұйрықтарды тіркеу журналы…», `Ручное распознавание журналов.docx`, `Ручное распознавание журналов2.docx`, `Сравнение нативного текста и сгенерированного приказа.docx`, `Требования к приказам по отпускам.docx` и сопоставленные XLSX-реестры. В ручном распознавании найдены примеры ухода за ребёнком, образования, стажа, ознакомления и исполнителя; ПДн и исходники в репозиторий не копируются.

Нерешённые вопросы: текущая модель требует отдельной проверки, что дата выдачи сертификата и его связь с основной специальностью материализованы; если нет, вывод сертификата блокируется. То же относится к формальной медицинской категории должности. Никакая генерация не создаёт события, назначения или не регенерирует старые editorial blocks.
