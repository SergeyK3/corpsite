# Общий каркас импорта и экспорта

## Граница предметных моделей

`hr_import_batches` и `hr_import_rows` остаются моделью контрольного списка;
архив операционных приказов остаётся отдельным intake-слоем. Новый каркас
использует собственные технические таблицы `data_exchange_*` и не принимает
имя таблицы, SQL или обработчик от клиента.

Пакет приказов создаёт только `personnel_order_import_review_records`.
Это review-staging: он не создаёт `personnel_orders`, `employee_events`,
назначения или персональные данные. Перенос в официальный учёт возможен лишь
после отдельного решения о канонической модели и через штатную команду
приказов.

## Реестр

Сценарий является серверным классом с фиксированными кодом, версией схемы,
допустимыми файлами, разрешениями, валидатором, preview, dry-run, бизнес-ключом
и apply. Динамической маршрутизации в таблицу базы данных нет. Первый
исполняемый сценарий: `PERSONNEL_ORDERS_REVIEW_IMPORT` /
`PERSONNEL_ORDERS_XLSX_V1` и `CONTROL_LIST_CATEGORIES_IMPORT` /
`CONTROL_LIST_CATEGORIES_XLSX_V1`. Категории требуют точной связки
batch/`hr_import_rows.row_id`/`employee_id` и повторно сверяют источник с
`normalized_payload.certification_raw`; HR corrections не перезаписываются.
Эталон сотрудников экспортируется отдельно и
содержит технический `employee_id` и контрольное ФИО.

Старый локальный скрипт категорий остаётся вне серверного runtime. Его
безопасная замена — зарегистрированный versioned scenario выше.

## Жизненный цикл

`UPLOADED → VALIDATING → PREVIEW_READY → DRY_RUN_PASSED →
AWAITING_CONFIRMATION → APPLYING → APPLIED`; при структурной или строковой
ошибке — `BLOCKED`, при техническом сбое — `FAILED`, оператор может отменить
`CANCELLED`. `DRY_RUN_PASSED` также фиксируется отдельной audit-записью перед
ожиданием подтверждения.

Подтверждение повторяет package ID, SHA-256, версию схемы и fingerprint
связанных сотрудников. Перед apply они вычисляются заново под блокировкой;
изменение файла, состава области видимости либо карточки сотрудника блокирует
применение. Apply выполняется одной транзакцией. Повторная загрузка того же
сценария/версии/SHA возвращает существующий пакет, а бизнес-ключ строки не
позволяет создать review-запись повторно.

## Безопасность

Пакеты ограничены 25 MiB, допускается только `.xlsx`; имя файла не содержит
путь. Проверяются ZIP-бомба, макросы и формулы. Ссылки на источники в XLSX
только относительные и без traversal. Экспорт экранирует строки, начинающиеся
с `=`, `+`, `-`, `@`. Ошибки API не отражают значения ячеек. Права независимы:
просмотр, upload/preview, dry-run, confirmation/apply и эталонный экспорт;
они всегда проверяются через явные access grants, без неявного ADMIN bypass.
Каждая операция использует организационную область видимости пользователя.

## Откат

Если apply не завершается, его транзакция откатывается, целевые review-записи
не остаются частично созданными, а пакет получает нераскрывающий деталей
статус `FAILED`. Откат схемы удаляет только технические таблицы и выданные ею
roles/grants; он не затрагивает кадровые таблицы.
