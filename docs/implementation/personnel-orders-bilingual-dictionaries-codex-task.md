# Задание Codex: начальные словари подразделений и должностей

## Цель

Пройти по доступным кадровым приказам и текущим справочникам Corpsite и
подготовить два отдельных начальных двуязычных словаря:

1. подразделения на казахском и русском языках;
2. должности на казахском и русском языках.

Это аналитическая задача. Код, API, БД, миграции и интерфейс не изменять.

`D:\ТОО\4 dept\4A soft\10A soft\27 Corpsite ММЦ\order_samples\2026 ПРИКАЗ\`

## Порядок работы

1. Прочитать из локальной БД текущие справочники организационных подразделений
   и должностей вместе с их ID и всеми уже существующими языковыми полями.

2. Рекурсивно извлечь из доступных DOCX/DOC тексты названий подразделений и
   должностей. Не собирать ФИО, ИИН и другие персональные данные в результаты.

3. Сохранить фактические варианты написания, включая сокращения и опечатки, но
   не объявлять их отдельными сущностями без необходимости.

4. Сопоставлять найденный термин с `unit_id` или `position_id` только при
   достаточном подтверждении. Не угадывать ID по одному похожему названию.

   Для подразделений действующий Excel-справочник `org_units` является
   приоритетным источником `unit_id`, `code` и русского названия `name`.
   Тексты приказов используются для казахских названий, исторических вариантов
   и проверки контекста.

5. Формировать языковую пару прежде всего по двуязычным приказам и уже
   существующим справочникам. Допустимо предложить перевод по смыслу, но его
   нужно пометить `PROPOSED`, а не `CONFIRMED`.

6. Не создавать два направленных перевода. Одна строка должна содержать оба
   равноправных названия: `name_kk` и `name_ru`.

7. Не объединять автоматически разные должности или подразделения из-за
   похожего написания. Все неоднозначности вынести в отдельный раздел.

## Результаты

Создать два файла:

- `docs/implementation/personnel-order-unit-names-bilingual-dictionary.md`;
- `docs/implementation/personnel-order-position-names-bilingual-dictionary.md`.

В каждом файле использовать таблицу:

| ID | Казахское название | Русское название | Варианты в источниках | Количество упоминаний | Статус | Источники/примечание |
|---:|---|---|---|---:|---|---|

Допустимые статусы:

- `CONFIRMED` — пара прямо подтверждена двуязычным источником или справочником;
- `PROPOSED` — перевод предложен по смыслу и требует проверки;
- `REQUIRES_REVIEW` — сопоставление или перевод неоднозначны;
- `SOURCE_ONLY_KK` — найден только казахский вариант;
- `SOURCE_ONLY_RU` — найден только русский вариант.

В конце каждого файла указать:

- количество уникальных найденных названий;
- количество `CONFIRMED`, `PROPOSED` и требующих проверки;
- несопоставленные варианты;
- файлы или форматы, которые не удалось прочитать.

Не включать в документы ФИО сотрудников и другие персональные данные.

## Контрольные значения

В словарях должны присутствовать либо быть явно вынесены на проверку термины
из приказа №104:

- `Терапия және паллиативтік көмек бөлімшесі`;
- `Қабылдау бөлімшесі`;
- `А блогы мейіргері`;
- `Күндізгі мейіргер`.

Обязательные рабочие переводы со статусом `PROPOSED`:

| Казахское название | Русское название |
|---|---|
| күндізгі мейіргер | медицинская сестра |
| А блогы мейіргері | медицинская сестра блока А |
| В блогының мейіргері | медицинская сестра блока Б |
| тәуліктік мейіргер | медицинская сестра круглосуточного стационара |
| палаталық мейіргер | палатная медицинская сестра |
| емшара мейіргер | процедурная медицинская сестра |

- Для `тәуліктік мейіргер` нельзя использовать перевод «дневная медсестра»:
  `тәуліктік` означает круглосуточный режим.
- Для `емшара мейіргер` нельзя использовать перевод «хирургическая медсестра».
- `А блогы` и `В блогы` пока остаются частью рабочего названия должности, но
  должны быть дополнительно сверены со справочниками организации.

- Ничего не добавлять в staged-набор.
