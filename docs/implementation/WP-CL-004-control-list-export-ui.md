## 1. Цель и границы

`WP-CL-004` добавляет пользовательский запуск утверждённого XLSX-экспорта в существующий раздел «Контрольный список». Интерфейс не показывает предварительно ИИН, телефоны или строки проекции и не создаёт дополнительный JSON-канал. Серверный источник остаётся единственным endpoint из `WP-CL-003`:

```text
POST /directory/personnel/control-list/export
```

Пакет не меняет состав книги, кадровые данные, серверный scope, permission, аудит и правила формирования XLSX.

## 2. Размещение и доступ

В ряду подразделов «Контрольного списка» после «Мед. категории» размещена опция «Экспорт». Маршрут страницы:

```text
/directory/personnel/control-list/export
```

Опция отображается только при точном значении `has_control_list_export === true` в действующей проекции `/auth/me`. Backend формирует этот признак через штатную проверку эффективного permission `CONTROL_LIST_EXPORT`; он не выводится из названия роли и не расширяет права ролей. Прямое открытие страницы без capability не показывает кнопку. Независимо от frontend-видимости endpoint повторно проверяет permission и организационный scope на сервере.

Панель содержит заголовок «Экспорт контрольного списка», предупреждение о выгрузке активного персонала и наличии персональных данных и кнопку «Экспортировать в Excel». Во время операции кнопка заблокирована, получает `aria-busy` и явный текст «Формирование файла…». Дополнительная синхронная блокировка не допускает второго запроса при двойном клике.

## 3. Выбор имени и места сохранения

### 3.1. File System Access API

Если `window.showSaveFilePicker` доступен, он вызывается непосредственно из обработчика пользовательского клика до первого запроса к backend. Диалог предлагает имя `Контрольный_список_YYYY-MM-DD.xlsx`, где дата вычисляется в `Asia/Almaty`, и ограничивает выбор MIME-типом XLSX и расширением `.xlsx`.

После выбора выполняется запрос. Только полностью полученный и успешно проверенный Blob записывается в выбранный файл, после чего writable stream закрывается. При ошибке записи выполняется доступный `abort`; backend повторно не вызывается. Отмена диалога (`AbortError`) завершается без запроса и без сообщения об ошибке.

### 3.2. Браузерный fallback

Если File System Access API отсутствует, клиент получает Blob, извлекает предпочтительное UTF-8-имя из `Content-Disposition`, очищает управляющие символы, компоненты пути и недопустимые для имени символы, заменяет постороннее конечное расширение и гарантирует расширение `.xlsx`. Повреждённое `filename*` не подавляет безопасный ASCII fallback. Затем создаются Blob URL и временная ссылка с атрибутом `download`. После клика ссылка удаляется сразу, а освобождение Blob URL откладывается до следующей задачи event loop, чтобы браузер успел начать скачивание.

Место сохранения в fallback определяется только настройками браузера. Приложение не выбирает локальную папку пользователя самостоятельно.

## 4. Целостность и безопасность

- запрос выполняется методом `POST` с `cache: "no-store"` и существующим Bearer-заголовком;
- если сервер прислал `X-Content-SHA256`, SHA-256 проверяется через Web Crypto до записи или браузерного скачивания;
- неверный формат checksum, недоступность проверки и несовпадение прекращают операцию без сохранения;
- ответ принимается как файл только с MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`;
- Blob и его содержимое остаются локальными переменными операции и не записываются в React state, `localStorage`, IndexedDB или логи;
- сторонняя аналитика экспорта не добавлена;
- `Content-Disposition`, `X-Content-SHA256` и `X-Request-ID` доступны браузеру через `Access-Control-Expose-Headers` для действующей cross-origin конфигурации frontend/backend.

## 5. Ошибки и доступность

| Условие | Сообщение интерфейса |
| --- | --- |
| HTTP 403 | «Недостаточно прав для экспорта контрольного списка» |
| HTTP 409 | «Обнаружены ошибки основных назначений. Файл не сформирован.» |
| Ошибка SHA-256 | «Не удалось проверить целостность файла. Файл не сохранён.» |
| Ошибка записи выбранного файла | «Не удалось записать выбранный файл. Повторный запрос к серверу не выполнялся.» |
| Остальные безопасные ошибки | «Не удалось сформировать файл. Повторите попытку или обратитесь к администратору» |

Сообщения не включают тело ответа, SQL, traceback, внутренние идентификаторы или персональные данные. Ошибки объявляются через `role="alert"`, успешное состояние — через `role="status"`; состояние не обозначается только цветом. Кнопка является нативным элементом `button` с доступным текстовым именем и сохраняет штатную клавиатурную навигацию. Контейнер и ряд подразделов используют существующую адаптивную раскладку.

## 6. Совместимость браузеров

Системный диалог используется только в браузерах, реализующих File System Access API. Локальные TypeScript-типы описывают лишь фактически используемые методы и не требуют новой зависимости. Во всех остальных поддерживаемых браузерах применяется стандартное скачивание через Blob URL. Web Crypto требуется только тогда, когда сервер передал обязательный для проверки `X-Content-SHA256`; endpoint `WP-CL-003` передаёт этот заголовок.

## 7. Тесты и критерии приёмки

Frontend-тесты покрывают:

- видимость опции и страницы по capability и сохранение существующих подразделов;
- порядок размещения после «Мед. категории» и активное состояние маршрута;
- вызов picker до backend, XLSX-фильтр и предлагаемое имя;
- отмену без запроса, fallback и очистку DOM/Blob URL;
- безопасный разбор `Content-Disposition` и обязательное расширение `.xlsx`;
- успешную и неуспешную SHA-256-проверку до скачивания;
- 403, 409, общую ошибку и ошибку записи;
- блокировку повторного клика и loading/disabled-состояние;
- отсутствие записи в браузерные хранилища.

Backend-тест подтверждает точную capability в `/auth/me` без вывода права из роли и CORS-доступность заголовков бинарного ответа. Регрессионный тест endpoint `WP-CL-003` подтверждает сохранение серверного RBAC-контракта.

Критерии приёмки:

1. Пользователь без `CONTROL_LIST_EXPORT` не видит опцию или кнопку и не может получить файл от backend.
2. Picker открывается до запроса; отмена не создаёт экспорт и аудит запроса.
3. В fallback используется серверное безопасное имя, а временные браузерные ресурсы всегда освобождаются.
4. Blob сохраняется только после успешного HTTP-ответа и проверки целостности.
5. Существующие подразделы контрольного списка продолжают работать.

## 8. Ручная проверка

В браузере необходимо подтвердить нативный вид системного диалога и фактическую запись файла в Chromium с File System Access API, стандартный download в браузере без API, поведение при ручной отмене/ошибке записи и адаптивность панели на узком экране. Реальный доступ следует проверить учётными записями с эффективным персональным или ролевым `CONTROL_LIST_EXPORT` и без него; серверная проверка остаётся окончательной.
