# Независимые кадровые шаблоны — третий этап

Рабочая локальная БД `corpsite` не мигрировалась: её ревизия остаётся `za0b1c2d3e4f`. Проверка выполняется на `corpsite_test`, отдельном backend `127.0.0.1:8013` и frontend `127.0.0.1:3013`. Серверные команды ниже агент не выполняет.

Миграции: `orgkk001 → hrlang001 → hrtpl001 → hrrecall001`. `hrtpl001` добавляет самостоятельные шаблоны и привязывает существующие версии к одному шаблону по умолчанию для каждого вида. `hrrecall001` расширяет ограничения вида приказа кодом `LEAVE.ANNUAL.RECALL` и делает составной FK вида шаблона отложенным для атомарной перепривязки. Миграции не создают тестовых пользователей, ролей, публикаций, приказов или кадровых событий. ID версий, номера, статусы, тексты и история применения сохраняются.

В окончательный третий этап входят подбор сотрудника с ФИО и подразделением, заполнение доступных RU/KZ-значений и редактируемые основания из существующих падежных форм ФИО. Неопределённая форма остаётся для ручного ввода. Поддержка отзыва ограничена созданием, редактированием и формированием текста черновика: ставка, пересчёт отпуска и кадровые события не добавлены. Восемь текстовых полей, отдельные основания RU/KZ и выбранная версия сохраняются через штатный API.

Карточка, редактор и диалог копирования используют один `template_id`; каждый новый вызов диалога берёт текущую карточку. Диалог содержит поиск исходника и два пустых свободных поля названий; вид наследуется от исходника. Копия — самостоятельный неопубликованный черновик v1. Изменение вида доступно отдельно только для независимого, ещё не использованного черновика без истории публикаций и сохраняет тексты. Несовместимые переменные не переименовываются и блокируют публикацию. Использованную копию можно архивировать с сохранением истории; неиспользованную — удалить по подтверждённому названию.

Исправлены загрузка версий, защита сохранения по `template_version_id` и revision, публикация без искусственной правки текста, сообщения об ошибках и подтверждения успеха. Параллельное чтение освобождает соединения до вложенной проверки прав; сами правила прав сохранены. Поиск списка приказов учитывает сохранённый заголовок, совместно с отдельным фильтром сотрудника.

Кнопка «Создать на основе…» находится вверху карточки выбранного шаблона в одной строке с открытием редактора. На казахском она подписана «Негізінде жасау…». Если сохранённых версий ещё нет, доступно копирование встроенной основы: создаётся независимый черновик без сохранения или публикации исходного содержания. Для этой правки дополнительная миграция не нужна; права `require_sysadmin_api` сохранены. Под `template_review` оба сценария проверены через настоящий вход, API и браузер.

Выбранный при создании `template_version_id` сохраняется в приказе. Формирование и применение полного RU/KZ-содержимого через существующий механизм проходят в одной транзакции. Последующая публикация не переключает сохранённую ссылку. Название варианта не заменяет заголовок документа; общий язык раздела не меняет язык документа.

## Перенос

В третий этап включена проверка UI-доступа к `/admin/templates` и его вложенным страницам по существующему `has_sysadmin_api`, с сохранением доступа системного администратора с `role_id=2`. Остальные проверки маршрутов и полный административный интерфейс не расширяются. API продолжает использовать прежний `require_sysadmin_api`. Стандартные `ADMIN` и `HR_HEAD` меняют общий язык по существующей проверке кода роли; она не изменялась.

Назначение `ADMIN` тестовому пользователю `template_review`, его персональные разрешения, тестовые пользователи и роли, публикации и копии шаблонов из `corpsite_test` в рабочие базы не переносятся. Пакет содержит код, миграцию структуры и инструкции; дампов и скриптов наполнения тестовыми данными в нём нет.

Обновлённый пакет `runtime/corpsite-personnel-template-variants-20261006.zip` содержит узкие патчи для трёх состояний исходников: до первого этапа, после первого и после второго, а также связанный код и тесты в `source/`. Посторонние правки справочника должностей и формулировок исключены. В источники названий добавлен только вид отзыва; прежние записи и ресурсы шаблонов не заменяются. При конфликте патча остановиться и согласовать конкретный конфликт; не копировать поверх исходников папку `source/`, локальную папку `app` или `corpsite-ui`. Пакет воспроизводится скриптом `scripts/build_personnel_template_stage3_package.py` из выбранной git-ревизии.

Из локального корня проекта пользователь переносит ZIP и SHA256:

```powershell
scp .\runtime\corpsite-personnel-template-variants-20261006.zip .\runtime\corpsite-personnel-template-variants-20261006.zip.sha256 corpsite:/tmp/
```

Далее в своём серверном терминале:

```bash
set -euo pipefail
HR_TEMPLATE_REPO=/opt/projects/corpsite/app
HR_TEMPLATE_PACKAGE=/tmp/corpsite-personnel-template-variants-20261006
cd /tmp
sha256sum -c corpsite-personnel-template-variants-20261006.zip.sha256
cd "$HR_TEMPLATE_REPO"
.venv/bin/python -m zipfile -e /tmp/corpsite-personnel-template-variants-20261006.zip /tmp
cd "$HR_TEMPLATE_PACKAGE"
sha256sum -c SHA256SUMS
cd "$HR_TEMPLATE_REPO"
.venv/bin/python -m alembic current
.venv/bin/python -m alembic heads
HR_TEMPLATE_REVISION=$(.venv/bin/python -m alembic current | awk 'NF {print $1}')
case "$HR_TEMPLATE_REVISION" in orgkk001|hrlang001|hrtpl001) ;; *) printf 'STOP: unexpected revision %s\n' "$HR_TEMPLATE_REVISION"; exit 1 ;; esac
HR_TEMPLATE_PATCH=
for candidate in stages1-3.patch stages2-3.patch stage3.patch; do
  if git apply --check "$HR_TEMPLATE_PACKAGE/$candidate"; then HR_TEMPLATE_PATCH="$candidate"; break; fi
done
test -n "$HR_TEMPLATE_PATCH"
printf 'Selected patch: %s\n' "$HR_TEMPLATE_PATCH"
bash ./scripts/ops/check_cursor_remote.sh
mkdir -p "$HR_TEMPLATE_REPO/runtime"
HR_TEMPLATE_BACKUP=$(mktemp -d "$HR_TEMPLATE_REPO/runtime/hr-template-backup-XXXXXXXX")
printf 'Backup: %s\n' "$HR_TEMPLATE_BACKUP"
sudo systemctl stop corpsite-backend corpsite-frontend
.venv/bin/python "$HR_TEMPLATE_PACKAGE/check_release.py" --repo "$HR_TEMPLATE_REPO" --phase before --state "$HR_TEMPLATE_BACKUP/protected-before.json"
tar --exclude='corpsite-ui/node_modules' --exclude='corpsite-ui/.next/cache' --exclude='*/__pycache__' -czf "$HR_TEMPLATE_BACKUP/source-env-build.tar.gz" .env app alembic scripts corpsite-ui
.venv/bin/python "$HR_TEMPLATE_PACKAGE/backup_database.py" --repo "$HR_TEMPLATE_REPO" --output "$HR_TEMPLATE_BACKUP/database.dump"
test -s "$HR_TEMPLATE_BACKUP/database.dump"
cd "$HR_TEMPLATE_BACKUP"
sha256sum -c database.dump.sha256
sha256sum source-env-build.tar.gz > source-env-build.tar.gz.sha256
cd "$HR_TEMPLATE_REPO"
git apply --check "$HR_TEMPLATE_PACKAGE/$HR_TEMPLATE_PATCH"
git apply "$HR_TEMPLATE_PACKAGE/$HR_TEMPLATE_PATCH"
test "$(.venv/bin/python -m alembic heads | awk 'NF {print $1}')" = hrrecall001
.venv/bin/python -m alembic upgrade hrrecall001
.venv/bin/python -m alembic current
.venv/bin/python "$HR_TEMPLATE_PACKAGE/check_release.py" --repo "$HR_TEMPLATE_REPO" --phase after --state "$HR_TEMPLATE_BACKUP/protected-before.json"
sudo ./scripts/deploy_backend.sh
sudo ./scripts/deploy_frontend.sh
sudo systemctl is-active corpsite-backend corpsite-frontend
```

До и после миграции helper сравнивает прежние строки кадровых таблиц, включая историю применения, и контрольные суммы прежних записей источников названий. Он игнорирует только добавленные поля привязки и отдельное добавление вида отзыва в код. Никакой синхронизации содержимого шаблонов из локальных JSON/manifest при переносе не запускать. `stamp` не выполнять. Если серверная цепочка отличается, сначала восстановить и проверить реальные миграции; не подменять ревизию. Если `hrtpl001` уже применён и ни один патч не проходит, остановиться: для прежнего промежуточного пакета нужен проверенный адресный diff, повторное применение полного патча запрещено.

## Шаблон для отдельного импорта

`reference-data/personnel-templates/annual-leave-recall.json` содержит согласованные названия и все восемь текстовых полей без ID, сотрудников, акторов и статуса публикации из тестовой БД. Это отдельный файл для последующего импорта, не миграция и не автоматическое наполнение. JSON также лежит в ZIP отдельно от патчей: `templates/annual-leave-recall.json`.

После отдельного разрешения на импорт открыть карточку встроенной основы `LEAVE.ANNUAL.RECALL`, создать независимую копию через «Создать на основе…», взять названия из `name_ru/name_kk`, затем в редакторе перенести восемь полей из `texts` и сохранить через штатный API. Прочитать сохранённую версию повторно, проверить RU/KZ-просмотр и совместимость переменных. Оставить как DRAFT; публикация требует отдельного разрешения. Структура JSON предназначена для переноса текста через этот интерфейс; существующие команды синхронизации manifest не принимают этот формат напрямую.

После запуска проверить `/admin/templates?section=personnel-orders` и `/directory/personnel/orders`: группы, копирование версии, сохранение собственного черновика, явную публикацию, два варианта одного вида с различающимся текстом, RU/KZ-подписи, отдельный язык документа и создание без публикации. Управление остаётся под прежним `require_sysadmin_api`; кадровые права не расширяются.

## Ограничения и откат

Проверки окончательного состава третьего этапа на чистой копии: 180 связанных frontend-тестов, 53 проверки PostgreSQL/API/валидации и каталога; TypeScript без тестовых файлов. Проверена миграция в транзакции с откатом, сохранность строк, перепривязка без переписывания текста, публикация без изменения текста и создание по точной версии. Все три патча проверены на соответствующих исходных git-ревизиях; прежние записи источников названий сохранены. Настоящий браузер на 3013 подтвердил подбор сотрудника, редактируемые основания, полный RU/KZ-текст, создание черновика и поиск по сотруднику вместе с заголовком. Демонстрационные записи и отчёты этой проверки в пакет не входят.

В дополнительном старом тесте `test_selected_employee_return_from_childcare_generates_bilingual_document_context` обнаружено несовпадение регистра названия подразделения: ожидается `document unit`, генератор возвращает `Document unit`. То же падение воспроизведено на коммите `8cd8c4ec` до третьего этапа; несвязанная логика генератора не изменялась.

Сохраняется существующий набор переменных и предметных проверок каждого вида. Если для выбранного содержимого нет обязательных данных, создание завершается ошибкой без сохранения частичного приказа; другой шаблон автоматически не подставляется. Черновики и архивные версии не предлагаются для новых приказов. Сохранённые ссылки на впоследствии архивированную публикацию продолжают работать.

Добавлен только документный вид `LEAVE.ANNUAL.RECALL` в группу «Трудовой отпуск». Универсальный конструктор и кадровое применение отзыва не добавлены. Порядок семи групп и прежних видов сохранён. Downgrade `hrrecall001` запрещён при существующих приказах отзыва; downgrade независимых шаблонов запрещён после появления копий. Для полного отката после создания вариантов нужна согласованная остановка приложения и восстановление сохранённых БД, исходников и сборки из резервной копии.
