Порядок отдельного переноса при будущем деплое

Сделать резервную копию и сверить схему/историю миграций целевой БД. Отрепетировать
в изолированной копии. Сопоставлять группы по code, виды по job_code,
специальности по паре group.code + code и сверенному названию, должности по
точному существующему названию/контексту. Локальные числовые ID из инвентаризации
не переносить напрямую: это может перепривязать существующих сотрудников.
Подготовить и проверить отчёт INSERT/UPDATE/конфликтов до применения. Переносить
только согласованные строки и поля в транзакции; не удалять отсутствующие в
пакете записи и не переписывать сотрудников, назначения, приказы или снимки.
При архивировании сохранять используемые записи, меняя только is_active.
После переноса сверить семантические значения, ссылки, поиск RU/KK, создание
и повторное открытие тестового приказа. Сам push эти действия не выполняет.

названием потребует отдельного адресного обновления по согласованию: изменение
кода или шаблона не должно задним числом переписать существующий документ.
