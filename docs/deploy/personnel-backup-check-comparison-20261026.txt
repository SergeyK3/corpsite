ОГРАНИЧЕНИЕ И СЕМАНТИКА
Таблица public.personnel_section_settings, ограничение
personnel_section_settings_language_check.
Исходно:
CHECK (((language)::text = ANY ((ARRAY['kk'::character varying, 'ru'::character varying])::text[])))
После pg_restore:
CHECK (((language)::text = ANY (ARRAY[('kk'::character varying)::text, ('ru'::character varying)::text])))
Оба варианта разрешают kk, ru и NULL (обычная семантика CHECK). Приведение
varchar без ограничения длины к text не меняет содержимое констант. Приведение
массивом или по элементам сохраняет те же значения и порядок. Пустая строка,
другие значения и пробел после kk не принимаются обоими условиями.

ИСПРАВЛЕНИЕ
Нормализуется исключительно выражение (ARRAY[строковые константы::character
varying, ...])::text[] в массив с приведением каждого элемента к text.
Лексический разбор оставляет строки, quoted identifiers, dollar-quoted строки
и комментарии непрозрачными. Остальная часть CHECK сохраняется посимвольно.
Не удаляются CHECK, операторы, значения, приведения типов или ограничения длины.
Произвольные выражения, NULL-элементы и другие виды cast не нормализуются.
Сравнение схемы по-прежнему включает все ограничения, колонки, индексы,
триггеры, представления; дополнительно учитываются contype/convalidated/connoinherit.
Проверки данных всех таблиц, счётчиков и Alembic revision сохранены.
Версия подписи указана в manifest: check-literal-varchar-array-to-text-v2.
Старые manifest не переписываются; для них нужен соответствующий верификатор.
